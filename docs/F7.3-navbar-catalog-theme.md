# F7.3 — navbar consistency, catalog UX and theme refinement

Completed locally on 2026-11-20. Ready for owner visual acceptance; no publication, production provider changes or live database operations.

## Root causes and resolutions

1. **Equipment details navbar:** F7.2 scoped the continuous dark header surface to the exact catalog pathname through data-catalog. Details therefore retained the older translucent rgba(20,39,54,.97) surface and #567086 border against the #101f2b page. The shared header now marks both /equipment and /equipment/[id] with data-equipment. Both use the same page-surface token and transparent dividing border. The hidden pseudo-element keeps this color during its fade, avoiding a color swap at the scroll threshold. The existing floating inner surface, border, blur, shadow, 400ms transition, fixed height reservation and 112/80px hysteresis remain. Other routes retain their existing header surface rules; light styling is unchanged apart from the approved new control/alignment.
2. **Container alignment:** the header used width calc(100% - 64px), maximum 1536px and 24px horizontal padding, while the catalog uses min(1264px, calc(100% - 96px)), smaller-screen gutters and Tailwind caps. Expanded equipment headers now follow those actual content bounds, including 768px and 1024px breakpoint caps. At 1600px the logo link's left edge changed from 57px against a 168px hero edge to 169px against 168px: a 1px transparent-border allowance. The right-side control edge likewise aligns within 1px. Primary navigation retains its centered track; the floating capsule retains its established dimensions. Apply Filters was reviewed: its existing left edge and width align with the filter grid, and its tablet/mobile spanning behavior is appropriate, so it was not redesigned.
3. **Filter indicators:** Category, Rental type, Availability and Sort by now wrap the original native select with a decorative Lucide ChevronDown. Native appearance/background arrows are disabled to avoid duplicates, sufficient right padding is reserved, icons ignore pointer input, and theme text tokens provide contrast. Native labels, options, keyboard behavior, form names and server query construction are unchanged. Search remains text; Min/Max remain numeric inputs without chevrons.
4. **Theme default and placement:** the inline pre-paint initializer previously followed the OS when storage was missing/invalid, and the existing external-store subscriber listened to OS changes. Both now use Light as the fallback; only valid explicit light/dark values restore another preference. There is no OS listener. Existing localStorage/event infrastructure, guarded storage access, cross-tab updates and useSyncExternalStore remain; cleared/invalid cross-tab preferences also fall back to Light. One icon-only Sun/Moon button was moved from Footer to shared header-controls near the account actions. It is 44×44px, keyboard operable, labelled/titled, visibly focused and available directly on mobile/tablet and inside the floating header. Mobile account actions remain in the existing menu. Footer markup differs only by removal of its theme control; obsolete footer-control-only styles were removed.

The NobleNest reference was not found in the project or checked local reference locations. Placement follows the explicit F7.3 interaction/position requirements; exact comparison to an unavailable NobleNest screenshot remains for owner review. No other project or production site was changed.
