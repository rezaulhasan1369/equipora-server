# Equipora D0.6.1 — diagnostic adapter parsing correction

Predeployment validation snapshot. Base production commit:
`860890c98601e88bda023af3464ba5150410d801`.

## Confirmed defect and focused fix

The actual exported Netlify handler uses `serverless-http`, which supplies an
already-finished request with a Buffer body. The global `express.json()` skips
such requests, leaving the Buffer unparsed. The D0.6 diagnostic schema therefore
rejects a valid authenticated request with HTTP 400. Direct Express tests did
not reproduce this adapter behavior.

`src/app.ts` now registers middleware for the diagnostic path before the ordinary
JSON middleware. It authenticates first, accepts only POST with JSON UTF-8 and
identity encoding, checks declared and actual byte lengths, and parses the
adapter Buffer explicitly. Direct Express requests use a bounded raw-body reader
after the same authorization gate. The maximum diagnostic body is 2048 bytes.
Invalid UTF-8, malformed/empty JSON, inconsistent lengths, unsupported media or
encoding, and oversized payloads receive fixed sanitized rejections. The existing
proof schema is unchanged and still runs before any network probe.

Ordinary Express routes, MongoDB options, target restrictions, certificate
verification, probe deadlines, noncredential comparisons and cooldown are unchanged.
No production environment variables, Atlas rules, users, credentials, permissions,
frontend files, providers or dependencies are changed.

## Actual-handler regression coverage

`tests/netlify-diagnostic-body.test.ts` imports and invokes the actual exported
`netlify/functions/api.ts` handler, with MongoDB/network work mocked. It covers:

- Valid authenticated JSON, literal Buffer and base64 event bodies.
- Missing, invalid and unconfigured diagnostic keys, including malformed and
  oversized unauthorized payloads. A parser spy confirms those payloads are not
  JSON-parsed; network-probe counters remain zero.
- Malformed, oversized, empty, non-object and invalid-schema JSON.
- Unsupported content type, charset and compression, invalid UTF-8, and
  inconsistent declared length.
- Refusal of caller-supplied targets or query parameters, unchanged schema,
  sanitized responses and no-store behavior.
- Existing API health and database-health success/authorization through the handler.
