## Exact remaining decisions and production blockers

1. Profile email is read-only. The brief broadly says profile information can be updated but does not define identity-change security. Decide whether it is required; a safe implementation needs reauthentication, unique new-email handling, linked OAuth/account behavior and session invalidation. Do not silently enable insecure arbitrary email mutation.
2. Accept the new opt-in dark visuals. Four illustrative reviews meet the displayed field requirement; keep disclosure. A review database is an unrequested enhancement, not a release dependency.
3. Approve an actual reviewed Git manifest and genuine commit plan; only then commit/push. Counts remain below rubric thresholds until real history exists.
4. Approve persistent owner-controlled Stripe test configuration, exact frontend origin, Google callback, hosted signed webhook and secure initial Admin provisioning. No live payments. Claimable CLI sandbox lifecycle remains a separate deployment gate.
5. Approve coordinated ExonHost business release/Vercel frontend publication and exact-domain cookies/CORS/reload/provider acceptance. E8 infrastructure acceptance is preserved; it does not establish this uncommitted business release in production.
6. Confirm a provider-supported persistent scheduler lifecycle before removing local-only completion guards. Passenger sleep/restarts and multiple workers make an in-request/in-process production cron unsafe to assume. No production scheduler is started. Future mail needs privately entered SMTP host/port/user/password and a verified sender, TLS certificate validation, bounded delivery timeouts and opt-in activation. No real email configuration is present or changed.

The outbox has at-least-once delivery semantics at a real external transport boundary: a crash after delivery but before acknowledgment can duplicate mail. The deterministic message ID helps traceability but does not prove provider deduplication. Approval of real delivery requires reviewing those semantics, lease duration, retry exhaustion, monitoring and supported hosting execution. No paid service is required or introduced by this local preparation.
