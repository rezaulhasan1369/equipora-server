## Authoritative read-only backend contract

GET /api/equipment/selection accepts one strict ids query containing 1–8 comma-separated 24-hex IDs, normalizes/deduplicates them and returns only current approved non-deleted records in requested order. Unavailable quantity is retained honestly. No user history, database field or collection is created.

POST /api/equipment/:id/quote requires the existing JWT and Customer middleware. Strict inputs are start/end/quantity only; shared booking-period validation and the existing rentalPrice function compute days, rounded billing periods and cents from the current DB price. The response is marked estimate. It creates no reservations, payments or inventory changes. It rejects unauthorized roles, invalid/missing/unapproved records, caller prices and invalid periods/quantities. Date-specific overlapping holds and the final price remain verified by the existing transactional checkout. Availability is not guaranteed by a quote. No fees/taxes/delivery charges were added.

Canonical-link review also found a concrete pre-existing stock alias problem: upper/lower hex IDs identified the same MongoDB item but could be stored as different reservation strings. The isolated mixed-case concurrency test accepted **3 holds for stock 2** before correction. Booking-schema input now canonicalizes the equipment ID, and the identical concurrency test correctly accepts 2/rejects 1. Uppercase detail URLs now render and quote consistently. No Stripe session, reservation/payment identity or webhook transition logic was changed; existing private routes, reserve/checkout/fulfillment code and rentalPrice body remain byte-identical. No production data was inspected or migrated.
